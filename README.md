# 퍼즐앤메이플 (Puzzle & Maple)

> **방치형 매치3 퍼즐 RPG** — 무기 원소를 매치3로 터뜨려 5인 파티의 스킬을 발동하고, 스테이지를 돌파하며, 뽑은 영웅을 성급·스타포스로 키운다.

MapleStory Worlds(MSW) 플랫폼에서 **mLua**로 개발한 개인 프로젝트입니다.
퍼즐 입력 처리부터 전투·성장·재화 순환·랭킹까지 전 영역을 설계하고 구현했습니다.

| | |
|---|---|
| **플랫폼** | MapleStory Worlds (PC) |
| **언어** | mLua (Lua 5.3 확장) |
| **규모** | 스크립트 62개 · 화면 15개 · 밸런스 데이터셋 20종 |
| **구조** | 게임플레이 전부가 UI 공간에서 동작 (`.map`은 룸 컨테이너) |

---

## 핵심 루프

```
로비 ─→ 스테이지 진입 ─→ 퍼즐 드래그 ─→ 파티 공격 ─→ 적 턴 ─→ 층 클리어
 ↑                            (5층 = 보스)                          │
 └──────── 방치보상 · 가챠 · 성급/스타포스 성장 ←── 스테이지 클리어 ──┘
```

퍼즐 원소 6종이 곧 **무기 타입**입니다. 터뜨린 원소와 같은 무기를 든 영웅의 스킬이 발동하고,
주무기는 ×1.0 · 보조무기는 ×0.3(다른 타입) 또는 ×0.5(동일 타입) 배율로 기여합니다.
`Shield` 원소만 데미지 대신 쉴드를 부여합니다.

## 주요 시스템

| 시스템 | 내용 |
|---|---|
| **퍼즐** | 5×6 보드. 타일 하나를 드래그하는 동안 지나친 타일과 연속 교환, 캐스케이드 매칭. 드래그 10초 제한(타일을 따라다니는 시계 게이지) |
| **전투** | 5인 파티 턴제. 힐 → 버프 → 디버프 → 광역 → 단일 순으로 스킬 연출을 큐에 태워 순차 재생 |
| **스테이지** | 5층 = 1스테이지, 보스층은 5층. 몬스터 그룹 4개가 순환(한 바퀴 40스테이지)하며 스탯 곡선만 상승 |
| **시즌보스** | 3페이즈 + **무한 페이즈**. 무한 구간은 HP를 한 번만 채우고 공격력이 턴마다 복리로 증가 |
| **성장** | 가챠 → 중복 장수로 **성급**(등급별 임계값) → **스타포스** 강화(성공/유지/하락/파괴) |
| **랭킹** | 스테이지 최고 층 · 시즌보스 누적 딜량. `SortableDataStorage` 기반, 가상 스크롤 목록 |
| **재화** | 메소·결정석·티켓. 방치보상(10분 단위, 최대 12시간) |

## 핵심 구현

### 1. 드래그 입력 보간과 단계별 검증

MSW의 드래그 이벤트는 **프레임 단위로 샘플링**됩니다. 손이 빠르면 두 샘플 사이에서 여러 칸을 건너뛰고,
현재 칸만 처리하면 건너뛴 칸들이 밀리지 않아 조작이 씹힙니다.

문제는 이것이 **정확히 풀 수 없다**는 점입니다. 샘플 사이의 실제 궤적은 플랫폼이 제공하지 않는 정보이고,
샘플링 주기도 엔진이 결정합니다. 그래서 **완벽한 복원 대신 "추정 + 검증"** 으로 목표를 옮겼습니다.

**추정** — 이전 칸과 현재 칸을 직선으로 잇고 **체비쇼프 거리**(행 차이와 열 차이 중 큰 값)만큼 분할합니다.
격자에서는 대각선도 한 단계이므로, 이렇게 나누면 각 단계가 **자동으로 인접 이동**이 되어 교환 규칙을 그대로 만족합니다.

**검증** — 추정은 틀릴 수 있으므로 각 단계를 실제 보드 상태로 다시 확인합니다.

- 교환이 일어나면 좌표가 바뀌므로 **매 단계마다 자기 위치를 재조회**
- 행·열 모두 한 칸 이내인 경우에만 교환 허용 (건너뛴 단계 뒤 순간이동 방지)
- 직전에 교환한 타일과 **즉시 되교환되는 진동** 차단
- 위치 추적은 이동량 누적이 아닌 **절대 좌표 재계산** (드리프트 방지)

→ [`PuzzleController.mlua`](RootDesk/MyDesk/Component%20folder/Manager/PuzzleController.mlua)

### 2. 데이터 드리븐 밸런스 설계

몬스터 스탯 곡선, 스킬 계수, 가챠 확률, 스타포스 확률표, 성급 임계값까지 **전부 CSV(20종)** 로 뺐습니다.
수치를 바꿀 때 코드를 건드리지 않으므로 밸런스 반복이 빨라집니다.

데미지는 여러 배율이 곱으로 겹칩니다.

```
damage = atk × (AtkCoeff + 스타포스 스킬계수)
       × (1 + (매치수  − 3) × MatchCoeff)
       × (1 + 강화타일수      × EnhanceCoeff)
       × (1 + (콤보   − 1) × ComboCoeff)
       × 최종배율 × 적 받는피해배율
       × 10 / (10 + DEF)
```

곱연산이 4~5겹이라 **한 계수를 조금만 올려도 결과가 크게 흔들립니다.**
그래서 수치를 코드에서 떼어내 CSV만 고치고 바로 재검증하는 흐름이 필수적이었습니다.

### 3. 서버·클라이언트 분리와 저장 비용

- 재화·영웅 보유·강화 결과 등 **결과에 영향을 주는 판정은 전부 서버**(`@ExecSpace("ServerOnly")`)에서 수행하고,
  클라이언트 값은 화면 표시 용도로만 씁니다. 예를 들어 보스 일일 도전 횟수는 클라가 잘못 알고 있어도 서버가 거부합니다.
- DataStorage는 **캐시 → 더티 플래그 → 주기적 flush** 패턴으로 묶어 호출 수를 줄였습니다.
- RPC 경계로는 **평탄한 스칼라만** 넘깁니다 (Struct·table을 넘기면 런타임 오류).

## 아키텍처

**Managers** (`/common/Manager/`)

| 스크립트 | 역할 |
|---|---|
| `GameManager` | 진입점. 런 시작과 파티 초기화 |
| `StageManager` | 진행 축. 스테이지·층 구성과 클리어 판정 |
| `BattleManager` | 전투 오케스트레이션. 스킬을 분류해 순차 연출 |
| `TurnManager` | Player → Resolving → Enemy 순환 |
| `PlayerManager` / `MonsterManager` | 파티·몬스터 슬롯, HP·쉴드·애니메이션 |
| `EnemySkillManager` | 적 스킬 트리거 3종(주기·HP 임계·페이즈 전환) |
| `SeasonBossManager` | 3페이즈 보스, 파츠 조립, 일일 도전 횟수 |
| `CurrencyManager` | 재화와 방치보상 |
| `UIManager` | 스택 기반 화면 전환 + 씬 전환 연출 |

**Global Logics** — `PuzzleLogic`(드래그·캐스케이드) · `HeroDataManager`(영웅 데이터·가챠·저장) ·
`RankingManager` / `RankingUI` · `EnhanceUI` · `MailManager` · `Queue`(연출 시퀀스) · `Effect` · `UISoundManager`

## 프로젝트 구조

```
RootDesk/MyDesk/
├── Component folder/Manager/   # 매니저 컴포넌트
├── Logic folder/               # @Logic 전역 싱글턴
├── UI folder/Components/       # 버튼 글루 스크립트
├── Model folder/               # .model
└── Dataset/                    # CSV 20종 (밸런스 소스 오브 트루스)
ui/                             # 화면 15개 (.ui)
map/                            # 룸 컨테이너 (.map)
```

## 실행

MSW 프로젝트라 **MapleStory Worlds Maker**에서 월드를 열어야 실행됩니다.
스프라이트·사운드 등 리소스는 RUID로 플랫폼 서버에서 참조하므로 저장소에는 포함되지 않습니다.
플랫폼이 월드마다 제공하는 API 정의(`Environment/`)도 재배포 대상이 아니라 제외했습니다.
